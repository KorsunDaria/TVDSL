
ЗАДАНИЕ 1. РЕГУЛЯРКА -> НКА -> ДКА -> МИНИМАЛЬНЫЙ ДКА


======================================================================  регулярка -> [1 НКА] -> [2 ДКА] -> [3 минимизация] -> [4 примеры]

======================================================================
ШАГ 1. НКА (любой эквивалентный)
  Простая регулярка: строй "по смыслу". Сложная: по Томпсону:
    символ a   : (i) -a-> ((f))
    A B        : конец A -ε-> начало B
    A | B      : новый старт -ε-> начала A и B; концы A и B -ε-> новый финал
    A*         : новый старт -ε-> начало A и -ε-> новый финал;
                 конец A -ε-> начало A и -ε-> новый финал
    A+ = A A*      A? = (A | ε)
  Обязательно: таблица переходов НКА.

ШАГ 2. ДКА (subset construction). Состояние ДКА = МНОЖЕСТВО состояний НКА
  1. Старт = {q0} (при ε: ε-замыкание)
  2. Для каждого нового множества S и символа c:
       T = объединение переходов всех состояний из S по c
       (при ε: потом ε-замыкание)
  3. Новое T в список. Пустое T = ловушка (петли по всем символам).
  4. Финал ДКА = множество, где есть ФИНАЛЬНОЕ состояние НКА.
  5. Стоп, когда новых множеств нет.
  Оформление: таблица (множество | по a | по b | финал?).

ШАГ 3. МИНИМИЗАЦИЯ ПО ГРУППАМ
  1. Группы: {финальные} и {нефинальные}.
  2. ПОДПИСЬ состояния = (в какую ГРУППУ ведёт a, в какую ГРУППУ ведёт b).
     Сравниваем ГРУППЫ, а не имена состояний.
  3. Внутри группы разные подписи -> разделить.
  4. После ЛЮБОГО разделения пересчитать подписи с новыми группами.
  5. Стоп, когда за целый раунд ничего не разделилось.
  6. Каждая группа = одно состояние. Все группы по одному состоянию
     значит ДКА уже минимален (так и пиши).

ШАГ 4. ПРИМЕРЫ
  Одна принимаемая и одна отвергаемая строка, с трассировкой:
  S0 -a-> S1 -b-> ...

ЛОВУШКИ
  - финал ДКА только если в множестве есть ФИНАЛ НКА
  - не забыть ловушку (пустое множество)
  - сравнивать группы, а не имена

ЗАДАНИЕ 2. ГРАММАТИКА: FIRST / FOLLOW / LL(1)


======================================================================  грамматика -> [1 лев. рекурсия] -> [2 факторизация] -> [3 FIRST]
             -> [4 FOLLOW] -> [5 проверка LL(1)] -> [6 таблица]
======================================================================

  РБНФ: [X] это (X | ε);  {X} это новый N ::= X N | ε.

ШАГ 1. ЛЕВАЯ РЕКУРСИЯ
    A ::= A α1 | A α2 | β1 | β2
    заменить на:
    A  ::= β1 A' | β2 A'
    A' ::= α1 A' | α2 A' | ε
  Косвенная рекурсия: сначала подставить правила B в A.

  КОСВЕННАЯ ЛЕВАЯ РЕКУРСИЯ (микро-объяснение)
    Прямая:     A ::= A α         A сразу начинается с A.
    Косвенная:  A ::= B ...       A начинается с B,
                B ::= A ...       а B начинается с A: через цепочку A снова
                                  оказывается в начале.
ШАГ 2. ЛЕВАЯ ФАКТОРИЗАЦИЯ
    A ::= α β | α γ    ->    A ::= α A'      A' ::= β | γ
  После шагов 1-2 ПЕРЕПИШИ грамматику целиком и работай с ней.

ШАГ 3. FIRST (с чего может начинаться вывод)
    FIRST(терминал) = он сам
    FIRST(X1 X2 X3) = FIRST(X1) без ε
                      + FIRST(X2) без ε, если ε ∈ FIRST(X1)
                      + FIRST(X3) без ε, если ε в обоих
                      + ε, если ВСЕ символы могут быть ε
    A ::= ε  =>  ε ∈ FIRST(A)
    FIRST(A) = объединение FIRST всех альтернатив

ШАГ 4. FOLLOW (что может идти сразу после)
    1. $ ∈ FOLLOW(стартового)
    2. A ::= ... B β        :  FOLLOW(B) += FIRST(β) без ε
    3. A ::= ... B          :  FOLLOW(B) += FOLLOW(A)
       A ::= ... B β, ε ∈ FIRST(β)  :  FOLLOW(B) += FOLLOW(A)
  Множества зависят друг от друга по кругу: ИТЕРАЦИИ. Начни с известного,
  остальные пустые, прогоняй правила, пока что-то добавляется.

ШАГ 5. ПРОВЕРКА LL(1) (по спискам)
  Только для нетерминалов с несколькими альтернативами.
  Для каждой альтернативы список "когда её выбирают":
    не может быть пустой  -> список = FIRST(альтернативы)
    может быть пустой     -> список = FIRST (без ε)  +  FOLLOW(A)
  Один символ в двух списках = КОНФЛИКТ.
  Нет повторов у всех нетерминалов = LL(1).
  Пустая альтернатива это ЛЮБАЯ, из которой выводится ε.
  Конфликт запиши: "нетерминал A, терминал t, правила A→α1 и A→α2".
  Неоднозначную грамматику факторизацией не вылечить: пиши конфликт.

ШАГ 6. ТАБЛИЦА
  Строки: нетерминалы. Столбцы: терминалы и $.
  Каждая альтернатива это отдельное правило A → α:
    для каждого t ∈ FIRST(α), t ≠ ε   : правило в клетку [A, t]
    если α может быть пустой          : правило в [A, t] для t ∈ FOLLOW(A)
  Пустая клетка = ошибка. Два правила в клетке = конфликт.

ЗАДАНИЕ 3. СЕМАНТИКА И ТИПЫ


======================================================================  Идём по программе СВЕРХУ ВНИЗ, держим СТЕК ОБЛАСТЕЙ.

======================================================================
СТЕК ОБЛАСТЕЙ
    {            -> push()     положить пустую область
    }            -> pop()      снять верхнюю область (её имена исчезают)
    insert(x,T)  -> записать x:T в ВЕРХНЮЮ область.
                    Уже есть в верхней -> ОШИБКА "повтор"
    lookup(x)    -> искать СВЕРХУ ВНИЗ, брать первое найденное.
                    Нигде нет -> ОШИБКА "не объявлена / вне области"
  Затенение разрешено. Повтор ошибка только в ТОЙ ЖЕ области.

ПРАВИЛА ТИПОВ (изнутри наружу)
    5                       : int
    true / false            : bool
    x                       : тип из lookup
    e1 + e2, -, *           : оба int  -> int
    e1 < e2, >, ==          : оба int  -> bool
    new int[e]              : e int    -> int[]
    a[i]                    : a int[], i int -> int

ЧТО ДЕЛАТЬ С КАЖДОЙ СТРОКОЙ
    let x = e;      1) тип(e)
    let x: T = e;   2) T указан и T != тип(e)  -> ОШИБКА
                    3) insert(x, T или тип(e)) -> ОШИБКА, если x в верхней
                    (СНАЧАЛА правая часть, ПОТОМ insert)
    x = e;          1) lookup(x) не нашли      -> ОШИБКА
                    2) тип(x) != тип(e)        -> ОШИБКА
    if (e)/while (e): тип(e) != bool           -> ОШИБКА; тело { } это push..pop
  Использование до let и после закрытия области: ошибка.

ПОСЛЕ ОШИБКИ НЕ СТОП (метка error)
    имя не найдено                    : одна ошибка, тип узла error
    операнд уже error                 : результат error, НОВУЮ ошибку не писать
    типы не те (bool + int)           : одна ошибка, результат по сигнатуре
                                        (+ даёт int, < даёт bool)
    let с ошибкой справа              : переменную ОБЪЯВИТЬ (тип T из
                                        аннотации, иначе error)
    повтор имени в той же области     : новая запись НЕ добавляется

ОФОРМЛЕНИЕ
    1. Таблица символов: область | имя | тип | строка
    2. Ошибки: строка N: что и почему
    3. Выведенные типы: только переменные БЕЗ аннотации


ЛОВУШКИ
    - затенение не ошибка, повтор в одной области ошибка
    - внутри блока x может быть другой x (смотри сверху вниз)
    - после } имена блока не существуют
    - условие if (n) при n:int ошибка
    - операнд error даёт error без новой ошибки

ЗАДАНИЕ 4. TAC, CFG, ОПТИМИЗАЦИЯ ИЛИ БАЙТ-КОД



======================================================================  фрагмент -> [1 TAC] -> [2 блоки] -> [3 CFG] -> [4а оптимизация | 4б байткод]

======================================================================
ШАГ 1. TAC (не больше 2 входов и 1 результат в инструкции)
    x := c    x := y    x := y op z    x := op y    x := load a[i]
    L:        goto L    if x goto L    return x
  Выражение раскладывать ИЗНУТРИ НАРУЖУ, константы в временные:
    r = a[x] + 1  ->  t2 := load a[x]
                      t3 := 1
                      t4 := t2 + t3
                      r  := t4

  if/else:                           while:
          <условие в t>              L_cond: <условие в t>
          if t goto L_then                   if t goto L_body
          goto L_else                        goto L_end
    L_then: <A>                      L_body: <тело>
          goto L_join                        goto L_cond
    L_else: <B>                      L_end:
    L_join:
  Метки не повторять (L_then2, L_join2).

ШАГ 2. БАЗОВЫЕ БЛОКИ
  Лидеры (начала блоков):
    1) первая инструкция
    2) любая инструкция с меткой
    3) инструкция сразу после goto / return
       (пара "if..goto L1" + "goto L2" это один конец блока)
  Блок: от лидера до инструкции перед следующим лидером.

ШАГ 3. CFG (рёбра по ПОСЛЕДНЕЙ инструкции блока)
    goto L                    : одно ребро в блок с L
    if t goto L1 + goto L2    : два ребра, true в L1, false в L2
    return                    : рёбер нет (выход)
    иное (блок кончился перед меткой): ребро в следующий блок
  Отметить вход и выход. У while есть стрелка НАЗАД к блоку с условием.

ШАГ 4а. ОПТИМИЗАЦИЯ (одна, показать "до" и "после")
  CONST PROP: таблица "переменная -> константа", сверху вниз внутри блока:
    1) заменить операнды из таблицы
    2) все операнды константы -> вычислить, получить x := c
    3) x := c -> записать x в таблицу
    4) x получила не константу -> убрать x из таблицы
    В НАЧАЛЕ каждого блока таблица ПУСТАЯ.
    Пример: t1 := 3; t2 := t1 + 4; t3 := t2 < 10  ->  t2 := 7; t3 := true
    Алгебра: x+0=x, x*1=x, 0*e=0, e/e=1
  DCE: идти СНИЗУ ВВЕРХ, live = нужные после блока переменные:
    x := e : x не в live И e безопасно -> УДАЛИТЬ
             иначе live = (live \ {x}) + переменные из e
    Безопасно = нет побочных эффектов и не может упасть (деление не удалять).
  CSE: таблица "выражение -> переменная", сверху вниз:
    x := y op z : выражение уже есть -> x := (та переменная)
                  иначе добавить
    Операнд присвоен заново -> удалить из таблицы выражения с ним.
    Пример: t1 := a + b; t2 := a + b  ->  t2 := t1

ШАГ 4б. СТЕКОВЫЙ БАЙТ-КОД И ГЛУБИНА СТЕКА
    1) Слоты: параметры с 0 по порядку, потом локальные.
    2) Выражение в постфиксной форме: a + b * 2  ->  a b 2 * +
    3) Элемент в инструкцию:
         переменная         iload k (iload_0..3)      стек +1
         константа 0..5     iconst_c                  стек +1
         другая константа   ldc c                     стек +1
         + - * /            iadd isub imul idiv       стек -1
         x = ...            istore k                  стек -1
    4) После КАЖДОЙ инструкции записать глубину стека. Ответ = МАКСИМУМ.
  Формула проверки: глубина(лист)=1;
                    глубина(L op R) = max(глубина(L), глубина(R)+1)
  Пример c = a + b * 2 (слоты 0:a 1:b 2:c):
     iload_0 [a] 1 | iload_1 [a,b] 2 | iconst_2 [a,b,2] 3 (макс) |
     imul [a,b*2] 2 | iadd [a+b*2] 1 | istore_2 [] 0
  Ветвление: x < y -> iload x; iload y; if_icmplt L_true; goto L_false
             (суффиксы: eq ne lt le gt ge); ifeq L (прыжок, если на вершине 0)
  Дисциплина стека: стек не уходит в минус; на каждой метке одинаковая
  глубина со всех путей.

SSA (если спросят): каждая версия переменной определяется один раз,
  в точке слияния phi:   x3 := phi(x1, x2)

ЛОВУШКИ
    - в одной инструкции не две операции
    - у while нужна стрелка назад
    - у if две стрелки (true и false)
    - константу из прошлого блока в новый не переносить
    - CSE нельзя после изменения операнда
    - iconst_ только 0..5, дальше ldc
    - глубина стека это максимум размера стека, а не число iload

ПРИМЕР ДЛЯ ЗАДАНИЯ 3



======================================================================Программа:

======================================================================
  1   let size = 3;
  2   let arr = new int[size + 1];
  3   let pos = 0;
  4   let found: bool = false;
  5   while (pos < size) {
  6       let cur = arr[pos];
  7       if (cur == 2) {
  8           let found = true;
  9           pos = pos + cnt;
 10       }
 11       let cnt = 1;
 12       pos = pos + 1;
 13   }
 14   if (found) {
 15       let pos = arr;
 16       let size: bool = pos[0];
 17   }
 18   let size = size - 1;
 19   let done = pos == true;
 20   size = arr[done];

1. Таблица символов



ОТВЕТ
----------------------------------------------------------------------   G       | size  | int   | 1
   G       | arr   | int[] | 2

   область | имя   | тип   | строка
   --------+-------+-------+------------------------------------   G       | pos   | int   | 3
   G       | found | bool  | 4
   G       | done  | bool  | 19 (объявлена с ошибкой)
   B1      | cur   | int   | 6
   B1      | cnt   | int   | 11
   B2      | found | bool  | 8  (затеняет found из G)
   B3      | pos   | int[] | 15 (затеняет pos из G)
   B3      | size  | bool  | 16 (по аннотации, объявлена с ошибкой)

   Строка 18 в таблицу не попадает (повтор).

2. Ошибки

   строка | причина
   -------+-----------------------------------------------------------
   9      | cnt использована до объявления (объявлена в строке 11)
   16     | аннотация bool, а pos[0] имеет тип int
   18     | size уже объявлена в той же области G (строка 1)
   19     | pos == true: == требует два int, а true это bool
   20     | arr[done]: индекс должен быть int, а done это bool

   Не ошибки: строки 8 и 15 (затенение), строка 9 после первой ошибки
   (операнд error даёт error без новой ошибки), строка 20 присваивание.

3. Выведенные типы (только без аннотации)

   size (G) : int      arr : int[]        pos (G) : int
   cur : int           found (B2) : bool  cnt : int
   pos (B3) : int[]    done : bool

   (found в G и size в B3 имеют аннотацию, в список не входят.)

ПРИМЕР 1 ДЛЯ ЗАДАНИЯ 4: цикл + if без else



======================================================================Фрагмент (n: параметр):

======================================================================
   s = 0;
   i = 1;
   while (i < n) {
       if (i < 10) {
           s = s + i;
       }
       i = i + 1;
   }
   return s;

ШАГ 1. TAC
(if без else: ветка then проваливается в L_join, goto в её конце не нужен)
----------------------------------------------------------------------
   1       s  := 0
   2       i  := 1
   3   L_cond:
   4       t1 := i < n
   5       if t1 goto L_body
   6       goto L_end
   7   L_body:
   8       t2 := 10
   9       t3 := i < t2
  10       if t3 goto L_then
  11       goto L_join
  12   L_then:
  13       t4 := s + i
  14       s  := t4
  15   L_join:
  16       t5 := 1
  17       t6 := i + t5
  18       i  := t6
  19       goto L_cond
  20   L_end:
  21       return s

ШАГ 2. БЛОКИ
   Лидеры: 1 (первая), 3 (L_cond), 7 (L_body), 12 (L_then),
           15 (L_join), 20 (L_end)

----------------------------------------------------------------------
   b1 = строки 1-2     (s := 0; i := 1)
   b2 = строки 3-6     (L_cond: условие цикла)
   b3 = строки 7-11    (L_body: условие if)
   b4 = строки 12-14   (L_then)
   b5 = строки 15-19   (L_join: i := i + 1, возврат к условию)
   b6 = строки 20-21   (L_end: return)

ШАГ 3. РЁБРА
   b1 -> b2                      (блок кончился перед меткой)
   b2 -> b3 (true),  b2 -> b6 (false)
   b3 -> b4 
----------------------------------------------------------------------(true),  b3 -> b5 (false)
   b4 -> b5                      (блок кончился перед меткой L_join)
   b5 -> b2                      (goto L_cond, это ребро НАЗАД)
   b6: выход

        [b1  вход]
            |
            v
   +--->[b2  условие цикла]--false--->[b6  выход]
   |        |
   |      true
   |        v
   |    [b3  условие if]--false--+
   |        |                    |
   |      true                   |
   |        v                    |
   |    [b4  then]               |
   |        |                    |
   |        v                    |
   +----[b5  join, i:=i+1] <-----+

ШАГ 4а. ОПТИМИЗАЦИЯ: const prop, потом DCE
   Таблица const prop в начале КАЖДОГО блока пустая.

   Блок b3:
----------------------------------------------------------------------
      t2 := 10          таблица: t2=10
      t3 := i < t2      t2 -> 10:   t3 := i < 10   (i неизвестна, не считаем)
   Блок b5:
      t5 := 1           таблица: t5=1
      t6 := i + t5      t5 -> 1:    t6 := i + 1
      i  := t6          без изменений

   Почему i = 1 из b1 нельзя подставить в b3 и b5: i меняется в цикле.

   DCE (снизу вверх). Живы после b3 и b5: {i, n, s}.
   Блок b5:   goto L_cond                  пропуск
              i  := t6      i в live       оставить, live = {n, s, t6}
              t6 := i + 1   t6 в live      оставить, live = {n, s, i}
              t5 := 1       t5 не в live   УДАЛИТЬ
   Блок b3:   goto L_join                  пропуск
              if t3 goto    читает t3      live = {i, n, s, t3}
              t3 := i < 10  t3 в live      оставить, live = {i, n, s}
              t2 := 10      t2 не в live   УДАЛИТЬ

   До:                              После:
   b3:  t2 := 10                    b3:  t3 := i < 10
        t3 := i < t2                     if t3 goto L_then
        if t3 goto L_then                goto L_join
        goto L_join
   b5:  t5 := 1                     b5:  t6 := i + 1
        t6 := i + t5                     i  := t6
        i  := t6                         goto L_cond
        goto L_cond

ШАГ 4б. ВМЕСТО ОПТИМИЗАЦИИ: БАЙТ-КОД
   Слоты: 0: n, 1: s, 2: i

           iconst_0
----------------------------------------------------------------------
           istore_1           ; s = 0
           iconst_1
           istore_2           ; i = 1
   L_cond:
           iload_2
           iload_0
           if_icmplt L_body   ; i < n
           goto L_end
   L_body:
           iload_2
           ldc 10
           if_icmplt L_then   ; i < 10
           goto L_join
   L_then:
           iload_1
           iload_2
           iadd
           istore_1           ; s = s + i
